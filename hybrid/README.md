# CourtOS reviewed frontier handoff

Work locally in the native assistant, deliberately choose a public or synthetic text to review, inspect the exact provider request, and approve one external analysis. The response can be brought back as a visible draft in the native assistant; a person chooses whether to submit it there. No document attachments or previous chat history are automatically sent to the provider. The workbench does not preload the earlier fictional exercise.

`backend.py` and `gateway.py` run under separate Unix identities. Only the gateway receives `ANTHROPIC_API_KEY` and any Stripe credential. The application reaches only loopback services; the gateway uses the fixed Anthropic Messages endpoint without tools or arbitrary URL fetching. Jobs and immutable packets are scoped by user and tenant and can be recovered after a reload.

Enable `OCL_REVIEWED_HANDOFF_ENABLED=true` in **both** application and gateway, plus `EXTERNAL_ENABLED=1` in the application. Set the same exact `EXTERNAL_MODEL` in both services. The workbench reports the configured model and only marks the gateway ready when the model and handoff setting agree. Configure a model verified for the operator's account; the service never silently substitutes another model. A missing key or disabled gateway fails closed. New deployments also require billing readiness (`BILLING_REQUIRED=true`, the default); billing remains disabled until the operator configures and validates it. See [the billing operating notes](billing/README.md).

Authenticated API (the existing Cloudflare JWT, session, Origin and CSRF checks apply):

- `GET /api/workbench` returns mode, local/frontier model status, limits, and only the owner's most recently prepared reviewed packet and associated job. It contains no sample documents, questions or old demo jobs.
- `POST /api/packets/reviewed` accepts exactly `{text,purpose,acknowledge_public:true}`. Text is limited to 12,000 UTF-8 bytes, purpose to 1,000; the whole HTTP body remains limited to 16 KiB. It returns the exact complete provider payload, SHA-256 hash, provider/model, expiry and packet ID. Preparing a preview does not call a model.
- `POST /api/packets/:id/send` accepts `{hash,billing:{quote_id,max_charge_micros,currency:"chf"}}` when billing is enabled and is a separate text-and-cost approval. An explicit isolated QA configuration with `BILLING_REQUIRED=false` and `BILLING_ENABLED=false` retains the legacy `{hash}` path; this is not the test-user launch configuration. It atomically reserves the existing frontier quota and consumes the packet once. A changed model, wrong hash, expired packet or duplicate submission is rejected before inference. The gateway independently verifies the HMAC, version-2 envelope, exact payload shape, system prompt, model and byte limits, and durably rejects replay.
- `GET /api/packets/:id` and `GET /api/jobs/:id` recover state without resending. Failed or timed-out provider calls stay consumed and are never retried automatically. Returned provider model IDs must match the configured model.

The public-text confirmation is the person's classification decision, **not an automatic proof of publicity or anonymisation**. Unlike the legacy fixed catalogue, reviewed text cannot be independently checked against a public source allowlist. All text in the preview, including the purpose, goes to Anthropic after approval; no other case context is attached. Outputs remain untrusted material for human review.

The existing durable frontier bounds remain one admitted call per account and ten across the pilot per UTC day by default. Failures count. There is at most one active job per account and two globally. To bound free preview storage, at most ten new reviewed previews per account and one hundred globally can be admitted per UTC day; an identical unsent preview is reused, and its original admission date is preserved. SQLite adds an idempotent `packets.kind` field on startup, classifying existing packets as `catalog`; historical records are retained.

The legacy `/api/bootstrap`, catalogue packets and synthetic local exercise remain available for compatibility. They are separate from `/api/workbench`; enabling reviewed handoffs does not add private inputs to the legacy catalogue route. The deployment must enforce the filesystem and network boundary described in `../ops/courtos/README.md`.
